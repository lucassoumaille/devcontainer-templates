---
description: Python implementation and API conventions
---

- Follow the repository's established framework, package manager, architecture, and naming conventions.
- Use explicit, intention-revealing names for functions, classes, variables, routers, and request/response schemas.
- Prefer simple code over unnecessary abstractions.
- Add or update tests for behavior changes and bug fixes.
- Use type hints where they improve clarity and fit the project.
- Do not add dependencies without justification.
- Keep docstrings and comments short; explain non-obvious intent or constraints, not what the code already says.
